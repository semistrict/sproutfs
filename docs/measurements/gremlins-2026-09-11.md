# Gremlins simulation campaign — 2026-09-11 UTC

Gremlins generated **237 mutations** in the migration package. The four
scheduled simulation scenarios killed **118**, allowed **93** to survive,
and timed out on **3**. Another **23** were not covered and were not executed.
No mutation was nonviable, and the independent command audit found no build
failures. The mutation phase took 11 minutes 49 seconds.

The 93 survivors represent 90 distinct mutated programs: three operator
results duplicate other mutations after formatting. Replaying those programs
against the complete migration and host suites killed **44**; **43** still
passed and **3** timed out. These are results from the frozen source snapshot,
before the reconnect regression described below was added.

This is evidence about `vmmigrate` under these workloads, not a project-wide
score. A survivor is not automatically a bug: some changes affect untested
inputs, accounting, resource retention or behavior equivalent for the cases
the tests exercise. Timeouts remain separate from confirmed failures.

## Scope and tool configuration

The run used the official **Gremlins v0.6.0 Darwin arm64 release**, verified
against its published SHA-256 checksum, with Go 1.26.6. The source copy includes
the existing uncommitted work and the earlier handoff-layout regression.
The original curated mutation runner and its catalogue are retained.

The five default operators generated arithmetic, conditional-boundary,
conditional-negation, increment/decrement and negative-expression mutations.
Generated protobuf code was excluded. The production files mutated were:

| File | Killed | Survived | Timed out | Uncovered |
| --- | ---: | ---: | ---: | ---: |
| `pagesource.go` | 40 | 43 | 0 | 1 |
| `peer.go` | 52 | 44 | 3 | 20 |
| `receive.go` | 16 | 5 | 0 | 1 |
| `vmmigrate.go` | 10 | 1 | 0 | 1 |

`GOFLAGS` selected only `TestScheduled.*Reproduces`, disabled test caching,
and enabled JSON test events for the audit. The audit confirmed that the only
top-level tests run were the scheduled log, volume, migration and host tests.
They used seeds 1–3, both creation orders and `GOMAXPROCS=4`.

Integration mode allowed the host scenario to detect faults in migration
code; `--coverpkg=./vmmigrate` included that execution in coverage. Without
integration mode, Gremlins normally tests only the mutated package. The run
used four workers and a timeout coefficient of ten.
[Gremlins command documentation](https://gremlins.dev/latest/usage/commands/unleash/)
describes these options.

A small PATH shim recorded the actual Go invocations, mutation diffs, test
events and exit statuses without changing arguments or exit codes. This
provides evidence independent of Gremlins' status labels. The three watchdog
interruptions are recorded explicitly; they were not counted as assertion
failures. The source snapshot's hashes were unchanged after Gremlins finished.

Gremlins reports **55.92% efficacy**, using 118 / (118 + 93). Its reported
mutation coverage is **90.17%**, excluding timeouts from that calculation.
Neither number accounts for whether a surviving program is equivalent.

## Confirmed gap: connection budget after disconnect

Gremlins changed `budget.connections--` to `budget.connections++` in
`PageSource.releaseConnection`. Both the scheduled scenarios and the full
migration/host suites passed with that mutation. The existing budget test
checked refusal while another connection remained open, but did not check
that closing a connection returned its reservation.

The new `TestPageSourceReusesConnectionBudgetAfterDisconnect` runs inside
`testing/synctest` and opens four sequential connections from the same peer
with a one-connection budget. Each must fetch the source's private bytes;
volume fallback cannot make the test pass. Between attempts, it closes the
backing and waits for the server to observe disconnection.

The unchanged implementation passes. Replaying the exact Gremlins mutation
with the new test fails on the second connection: it is refused and falls
back to zero volume bytes. This closes a test gap; no production fix was
needed. The full migration suite also passes with the additional test.

Evidence: [mutation](gremlins-2026-09-11/reconnect-mutation.diff),
[test addition](gremlins-2026-09-11/reconnect-test.diff),
[mutant failure](gremlins-2026-09-11/reconnect-red.log), and
[correct implementation](gremlins-2026-09-11/reconnect-green.log).
The other surviving programs have not been rescored after this test addition.

## What remains

The results identify gaps around implicit authentication, configuration
boundaries, accounting and paginated page serving. For example, two mutations
that break automatic authentication inference still pass the broader suites.
These need targeted input and lifecycle tests rather than more seeds alone.

Correct volume fallback can also conceal a broken peer-transfer path. One
mutation overwrites an explicitly configured page size with the default. The
scheduled scenarios still preserve guest bytes by reading volumes, while the
ordinary migration tests detect the change. Healthy migration tests need
source-page assertions to establish that the peer path was exercised.

The curated campaign remains useful alongside this one. Flipping a comparison
can reject a valid request and be caught by a healthy workload; removing the
whole validation check can preserve healthy behavior while accepting invalid
requests. Those mutations answer different questions.

## Reproduction and retained evidence

The [wrapper](../../scripts/mutate-gremlins.py) makes a new source copy and
invokes Gremlins directly:

```sh
python3 scripts/mutate-gremlins.py --gremlins /path/to/gremlins --dry-run
python3 scripts/mutate-gremlins.py --gremlins /path/to/gremlins
```

The initial [native results](gremlins-2026-09-11/results.json),
[run configuration](gremlins-2026-09-11/run.json),
[command audit](gremlins-2026-09-11/audit-summary.json), and
[survivor replays](gremlins-2026-09-11/triage/report.json) are retained.
Complete per-process logs are compressed beside the reports. Broader replays
use the original snapshot, run both complete affected suites, and retain exact
mutation diffs. They use 30–60 second test timeouts and report timeouts
separately. The audited source copy and replay overlays remain in the local
cache directory recorded in the run configuration.

The wrapper was checked with a dry run that identified the same 214 covered
candidates and 23 uncovered candidates. Gremlins' default thresholds are zero,
so its successful exit means the campaign completed, not that every mutation
was detected. Native results are preserved rather than rewritten around the
new regression.
